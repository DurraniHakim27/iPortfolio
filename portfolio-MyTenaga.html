Final Year Project

MyTenaga — Smart Energy Monitoring System

Building a complete IoT solution for real-time energy monitoring, automated billing calculations, and machine learning predictions.

Duration May — December 2025
Location Universiti Teknologi Petronas
Platform ESP32, Firebase, Web
01 — The Problem

Why Monitor Energy?

Most households in Malaysia receive an electricity bill at the end of the month with a single number — total consumption and total cost. There's no breakdown of when the energy was used, which appliances consumed the most, or how behavior affects the bill. You only know after the fact.

I wanted to change that. What if homeowners could see their energy use in real-time? What if they could understand their consumption patterns and make informed decisions to save money? And what if the system could even predict future bills based on current usage?

That was the starting point for MyTenaga — a smart energy monitoring system that brings transparency to household electricity consumption.

02 — The Approach

Designing the System

The system needed to accomplish three things: measure electrical parameters accurately, process and store the data reliably, and present it in a way that's actually useful to users.

Hardware: ESP32 + PZEM-004T

For measurement, I chose the PZEM-004T module, which can measure voltage, current, power, energy, frequency, and power factor. An ESP32 microcontroller handles data acquisition and WiFi communication. The hardware is installed at the distribution board, measuring the main incoming supply.

Backend: Firebase

For the backend, I used Firebase — Realtime Database for storing measurements, Cloud Functions for processing, and Authentication for user management. This choice meant I could focus on the application logic rather than server infrastructure.

Frontend: React Web App

The web dashboard provides real-time visualization, historical charts, and the billing calculations. Users can see their consumption by hour, day, or month, and understand exactly how their bill is calculated according to TNB's tariff structure.

03 — Key Features

What the System Does

Real-Time Monitoring

The system updates every few seconds, showing current power consumption, voltage, current, and power factor. Users can see the immediate effect of turning appliances on or off.

Automated TNB Billing

The system implements Malaysia's TNB residential tariff structure, including tiered pricing and the Renewable Energy Fund (KWTBB) surcharge. It calculates what your bill would be if the month ended today, helping you budget and avoid surprises.

Machine Learning Predictions

Using XGBoost, the system analyzes historical consumption patterns to predict future usage. This helps users understand trends and identify anomalies — like if your consumption suddenly increases without explanation.

Historical Analysis

Data is stored and can be viewed by hour, day, week, or month. Users can compare periods and understand how their consumption changes over time — seasonal patterns, the effect of new appliances, or the impact of behavior changes.

One unexpected insight from testing: the standby power of multiple devices adds up significantly. Users were often surprised to learn how much they were paying for devices that were "off" but still drawing power.

04 — Challenges

What I Learned Along the Way

Calibration Accuracy

The PZEM-004T modules needed calibration against a reference meter to ensure accuracy. I learned that cheap sensors can be surprisingly good if you take the time to calibrate them properly — but you do need that reference standard.

WiFi Reliability

Home WiFi isn't always reliable. I implemented buffering and retry logic to handle temporary disconnections gracefully, ensuring no data was lost during network hiccups.

TNB Tariff Complexity

Malaysia's electricity tariff has multiple tiers, surcharges, and conditions. Implementing the billing calculation correctly required careful reading of TNB's documentation and validation against actual bills.

ML Model Training

Training the XGBoost model required sufficient historical data and feature engineering. I learned that temporal features (time of day, day of week) were as important as raw consumption values for accurate predictions.

05 — Results

Project Outcomes

The MyTenaga system was successfully deployed and tested in a real household environment over several months. Key outcomes include:

  • Accurate real-time monitoring with <2% measurement error after calibration
  • Billing calculations matching actual TNB bills within 1%
  • Machine learning predictions achieving 90%+ accuracy for next-day consumption
  • User feedback indicating improved awareness of energy consumption patterns

06 — Reflection

What This Project Taught Me

MyTenaga was my introduction to full-stack IoT development — from soldering hardware to writing backend code to designing user interfaces. The biggest lesson was that the user experience matters as much as the technical implementation. A perfectly accurate monitoring system is useless if people don't understand or trust what it's telling them.

I also gained appreciation for the complexity of seemingly simple things. Calculating an electricity bill correctly, handling network interruptions gracefully, making predictions that people can actually use — these all required more thought than I initially expected.

Most importantly, this project reinforced my belief that engineering should serve people. The technology is interesting, but what matters is whether it helps someone understand their world a little better.
