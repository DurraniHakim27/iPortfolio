Project Story

Autonomous Navigation IoT Service Robot

Building a vision-based autonomous robot that navigates indoor environments using monocular depth estimation, sensor fusion, and IoT connectivity.

Duration Jan — Aug 2025
Location Malaysia
Platform Raspberry Pi 5 + Hailo-8
Focus Computer Vision & Navigation
01 — Context

The Problem & The Vision

The idea was simple but ambitious: create a robot that could move around on its own, sense its environment, and interact with it intelligently — all using only a single monocular camera. Unlike remote-controlled bots, this one needed to be fully autonomous, able to navigate toward objects as checkpoints, locate an industrial plant, and even monitor the plant temperature conditions in real time.

To achieve that, the robot had to answer two fundamental questions: what is around me and how far away is it. These are the same questions Tesla cars ask when they drive down the road, and we wanted to give our robot that same kind of vision — but without the expensive LiDAR sensors.

The challenge was clear: build a cost-effective autonomous navigation system using only affordable hardware and AI-powered computer vision, capable of operating reliably in indoor environments.

02 — The Approach

Hardware & Architecture

At the heart of ThermoVision is a Raspberry Pi 5 paired with a Hailo-8 AI accelerator (26 TOPS). The Hailo chip was essential — without it, YOLO object detection ran at only 7 frames per second and SCDepth depth estimation could not run at all. With the accelerator, both models ran smoothly in parallel.

The hardware architecture combines vision, thermal sensing, and motor control into an integrated system:

Key Components

  • Raspberry Pi 5 — Main processing unit running the navigation algorithms
  • Hailo-8 AI Accelerator — 26 TOPS neural network inference for real-time vision
  • Pi Camera Module — Monocular camera for depth estimation and object detection
  • MLX90614 — Infrared temperature sensor for non-contact thermal monitoring
  • ESP32 — WiFi-enabled microcontroller for IoT communication via MQTT
  • Mecanum Wheels — Omnidirectional movement for precise navigation
03 — Technical Implementation

Vision, Depth & Navigation

Seeing the World in 3D

We implemented a dual-model vision pipeline running on the Hailo-8 accelerator:

  • YOLO — Detects objects in real-time: sphere, cylinder, cuboid, cone, and the "plant" (represented by a Maggi Hotcup)
  • SCDepthV3 — Estimates the distance to detected objects using only a single camera frame

This approach mirrors Tesla's monocular vision system. Instead of expensive sensors like LiDAR, ThermoVision relies on AI to create a sense of depth from 2D images.

YOLO real-time object detection identifying checkpoints

Navigation Logic

With stable depth readings, the robot follows a simple but effective navigation strategy:

  • When no target is detected, rotate clockwise/counter-clockwise to scan surroundings
  • Once the target is in frame, align the robot so the object is centered
  • Move forward while making micro-adjustments with hysteresis to prevent oversteer
  • Stop when the distance to target is less than ~23 cm
04 — Challenges

The Flicker Problem

Here's the disadvantage of AI depth estimation: the depth numbers flickered. A cone at 26cm could read 25cm the next frame and 29cm the frame after. This caused ThermoVision to inch forward, stop abruptly, then creep again. Watching it reminded me of someone learning to drive stick for the first time — lots of jerks and pauses.

The solution wasn't about running bigger models or collecting more data. The raw output needed stability. We applied a signal processing technique: the Exponentially Weighted Moving Average (EWMA) filter. EWMA smoothed the depth readings by giving more weight to recent values while still considering historical data.

Blue line shows the flickering raw depth values; orange line shows the smoothed output after EWMA filtering

The effect was immediate. The numbers steadied, and ThermoVision's movements became smooth and confident. Sometimes the simplest solutions — a well-chosen filter — outperform complex model retraining.

Other Technical Hurdles

  • Sensor Calibration — The thermal sensor required careful calibration to provide accurate readings at varying distances
  • Obstacle Detection — Balancing detection sensitivity to avoid false positives while not missing real obstacles
  • Path Planning — Implementing robust path correction when the robot deviated from its intended trajectory
  • Real-time Constraints — Ensuring all processing happened fast enough for responsive navigation
05 — IoT Integration

Plant Temperature Monitoring

The final checkpoint in the robot's journey was the "plant" — a simulated industrial unit represented by a Maggi Hotcup. ThermoVision uses an MLX90614 infrared sensor to measure temperature without contact. This data isn't just logged locally; it's part of an IoT ecosystem.

The onboard ESP32 transmits temperature readings via MQTT to another ESP32 at the plant control station. If the temperature exceeds a defined threshold, a cooling fan automatically activates. Once the temperature drops below the threshold, the fan turns off and ThermoVision retraces its journey in reverse order.

This architecture demonstrates how autonomous robots can integrate with industrial IoT systems — not just navigating autonomously, but also participating in distributed control loops.

06 — Results

What We Achieved

The project produced a fully functional autonomous navigation system:

  • A working robot capable of autonomously navigating indoor spaces using only monocular vision
  • Real-time object detection and depth estimation at 30+ FPS with Hailo-8 acceleration
  • Smooth navigation behavior through EWMA-filtered depth readings
  • Complete IoT temperature monitoring system with automated cooling response
  • Cost-effective implementation using affordable consumer hardware

07 — Reflection

What I Learned

This project reinforced that robotics is the intersection of multiple disciplines — computer vision, embedded systems, control theory, and hardware integration. The challenge wasn't just getting individual components to work, but making them work together in real time.

The flicker problem taught me an important lesson: sometimes elegant mathematics (EWMA filtering) beats brute-force approaches (bigger models, more data). Understanding the fundamental nature of your problem — in this case, noisy temporal data — leads to better solutions than throwing more compute at it.

I also gained appreciation for edge AI acceleration. The Hailo-8 transformed what was possible on a Raspberry Pi, enabling real-time inference that would otherwise require a full desktop GPU. This is the future of robotics — powerful AI running on efficient, affordable hardware.

Most importantly, I learned the satisfaction of watching a robot you've built make its own decisions, navigate its environment, and complete its mission. There's something magical about the first time it works — when the code you've written becomes physical motion in the real world.
